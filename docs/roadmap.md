## 완료된 영역

### 여행 구성 및 온보딩

인솔자가 새 여행을 만들고 기간·구성원·모둠·장소를 채워 넣는 영역. 장소는 지도 검색으로
좌표를 확보하고 유래·문화유산 학습 콘텐츠를 붙일 수 있으며, 기존 엑셀 일정표나 종이
일정표 사진에서 데이터를 끌어오는 경로도 포함합니다.

- [x] 새 여행 생성 후 기간·구성원·모둠 입력 → 목록 화면에 카드로 표시
- [x] 장소 추가에서 이름 검색(Nominatim) → 후보 선택 → 핀 드래그로 좌표 미세조정 후 저장
- [x] 엑셀 일정표 가져오기 → 날짜·밴드·장소가 슬롯으로 채워짐
- [x] 좌표 없이 저장된 장소는 목록에서 "좌표 없음"으로 구분되어 다시 찾을 수 있음

관련: `src/pages/Setup.tsx`, `src/components/PlacePicker.tsx`, `src/components/ScheduleImport.tsx`, `src/excel.ts`, `src/ocr.ts`

### 일정 편성

하루를 조식·오전·중식·오후·석식·저녁 6밴드로 나눠 각 슬롯에 장소나 활동을 배치하는 영역.
식사 밴드도 활동 밴드와 동일하게 좌표 있는 식당 장소를 연결합니다.

- [x] 날짜별 6밴드에 장소 배치 → 일정 타임라인에 순서대로 표시
- [x] 식사 슬롯에서 식당 등록 → `kind: 'food'` 장소로 저장되고 슬롯의 `placeId`로 연결
- [x] 연속한 두 장소 사이의 이동 예상시간 표시
- [x] 목업 식당 추천 UI 전면 제거 (DB v5 마이그레이션)

관련: `src/pages/Schedule.tsx`, `src/pages/Itinerary.tsx`, `src/db.ts`

### 실시간 지도 안내

실시간으로 확인하고 도착 알림을 받는 영역. 실 GPS와 이동 시뮬레이션을 토글할 수 있습니다.

- [x] 좌표 있는 장소 2곳 이상 → 지도에 번호 마커와 하루 동선 점선
- [x] 내 위치 → 다음 목적지 주황 실선 경로와 남은 분·거리·도착 예정 시각
- [x] 목적지 반경 80m 진입 시 도착 배너 + 진동, 다음 목적지로 자동 전환
- [x] OSRM 실패·오프라인 시 직선거리 추정치로 대체하고 "추정치" 라벨 표시
- [x] 첫 위치 수신 시 지도 refit, 반경 밖에서 진입한 경우에만 도착 처리

관련: `src/pages/Live.tsx`, `src/components/LiveMap.tsx`, `src/geo.ts`

통신이 불안정한 여행지에서도 앱이 뜨고 지도가 보이게 하는 기반 영역.

- [x] 홈 화면 설치, 오프라인에서 앱 셸 로드
- [x] 한 번 본 지도 영역은 통신이 끊겨도 타일 표시 (런타임 캐시, 300개 상한)

## 진행 중 · 남은 영역

### 사진 갤러리 및 여행 기록

**상태: 부분** — 사진 업로드와 감상평은 동작하고, 슬라이드쇼 영상만 남았습니다.

- [x] 일정 슬롯과 갤러리에서 장소별 사진 업로드·조회
- [x] 사진마다 한줄 감상평
- [ ] 여행 사진을 로열티프리 음원과 함께 슬라이드쇼 영상으로 내보내기

음원 저작권 때문에 로열티프리 한정으로만 가능합니다. 우선순위는 낮습니다 — 데이터 보존이
해결되기 전에는 만들어도 함께 사라집니다.

관련: `src/pages/Gallery.tsx`

### 데이터 보존 및 공유

**상태: 미착수 · 최우선**

여행 데이터가 기기 로컬(IndexedDB)에만 존재해 생기는 유실·단절 문제를 푸는 영역.
브라우저 데이터를 지우거나 기기를 잃으면 여행 기록이 통째로 사라지고, 여러 명이 같은
여행을 실시간으로 공유할 수 없습니다.

- [ ] 여행 하나를 사진 포함 단일 파일로 내보내고 다른 기기에서 그대로 복원
- [ ] 브라우저 데이터를 지우거나 기기를 바꿔도 백업본으로 여행 기록 복구
- [ ] 인솔자가 짠 일정을 참가자가 받아 볼 수 있음

**왜 최우선인가:** 기능이 늘어날수록 잃을 것이 커집니다. 지금은 미션 점수·사진·일정이
전부 한 브라우저의 IndexedDB에 있고 복구 수단이 없습니다. 실시간 다중 사용자 동기화
(백엔드 도입)까지 갈지는 이 영역에서 결정하되, 백엔드 없이 되는 내보내기/가져오기가 먼저입니다.

**다음 단계:** 내보내기 포맷 설계(사진 blob 포함 여부·용량) → `db.ts` 전체 덤프/복원 →
가져오기 시 ID 충돌 처리 → e2e.

### 지도 인프라 전환

**상태: 미착수**

무료 공개 인스턴스(Nominatim 검색, OSRM 경로, OSM 타일) 의존을 사용량 정책과 가용성이
보장되는 상용 API로 옮길 수 있게 하는 영역. 교체 지점은 `src/geo.ts` 단일 모듈로 이미
격리돼 있습니다.

- [ ] 단체 40명 동시 사용에도 검색·경로 호출이 차단되지 않음
- [x] 공급자를 바꿔도 `src/geo.ts` 밖의 코드는 수정하지 않음
- [ ] 국내 지명·상호 검색 결과가 Nominatim 대비 개선됨

카카오/네이버 어느 쪽을 쓸지, API 키를 어떻게 배포할지(현재 "API 키 없음"이 차별점 중
하나라 정면 충돌)가 미결입니다.

### 알림 신뢰성

**상태: 미착수**

도착 알림과 위치 추적이 "앱이 열려 있을 때만" 동작하는 현재의 제약을 사용자에게 정직하게
드러내고, 가능한 범위에서 신뢰성을 높이는 영역. iOS PWA가 구조적으로 허용하지 않는
백그라운드 추적을 억지로 구현하는 것은 범위 밖입니다.

- [ ] 앱이 닫히면 알림이 오지 않는다는 점이 "지금" 탭에서 명확히 안내됨
- [ ] 주행 중 화면이 꺼지지 않게 유지 (Screen Wake Lock)
- [ ] 장시간 사용 시 위치 추적 정확도를 낮춰 배터리 소모를 줄이는 선택지

## 우선순위

1. **데이터 보존** — 유일하게 되돌릴 수 없는 리스크. 나머지보다 먼저.
2. **알림 신뢰성** — 대부분 안내 문구와 Wake Lock으로, 비용 대비 효과가 큼.
3. **지도 인프라 전환** — 실사용 규모가 커지기 전까지는 폴백으로 버팀.
4. **슬라이드쇼 영상** — 데이터 보존 이후.
