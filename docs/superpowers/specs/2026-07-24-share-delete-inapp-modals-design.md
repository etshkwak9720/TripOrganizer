# 설계: 공유·삭제를 앱 내부 모달로 (네이티브 팝업 제거)

## 배경 — 왜 필요한가

여행 목록(`src/pages/Trips.tsx`)의 **공유**·**삭제** 버튼이 모바일에서 아무 반응이 없다.
원인은 세 버튼 모두 브라우저 기본 대화상자에 의존하기 때문이다:

- 공유: `publishShare`가 `window.prompt('여행 비밀번호를 설정하세요…')`로 비번을 받고,
  이후 `window.alert`로 결과를 보여준다.
- 삭제: `handleDelete`가 `window.confirm(…)`으로 확인을 받는다.

`window.prompt` / `confirm` / `alert`는 **홈 화면에 설치한 PWA(standalone)**나
**카카오톡·인스타 등 인앱 브라우저**에서 조용히 무시되는 경우가 있다. 그 결과 prompt가
`null`을 반환→`publishShare`가 "비밀번호가 필요합니다"를 throw→그 alert도 안 떠서 **눌러도
무반응**이 된다. 삭제도 confirm이 `false`가 되어 아무 일도 일어나지 않는다.

해결: 네이티브 대화상자를 **앱 자체 모달**로 대체한다. 기존 "새 여행 만들기"
바텀시트(`CreateForm`, `fixed inset-0 z-50 flex items-end …`) 스타일을 재사용한다.

## 목표

- 모바일 PWA·인앱 브라우저를 포함해 어디서든 공유·삭제가 동작한다.
- 공유 시 인솔자가 앱 내부에서 비밀번호를 입력하고, 생성된 참여 링크·비번을
  복사/공유(카카오톡 등)/QR로 학생에게 전달할 수 있다.

## 범위 밖

- 비밀번호 자동 생성(이번엔 인솔자 직접 입력만)
- 참여자별 개인 계정, 사진 수명 관리 등 기존 후속 스펙 항목
- 링크에 비밀번호 삽입(게이트 유지를 위해 의도적으로 안 함)

## 결정된 설계

### A. 공유 흐름 — 여행 카드 "공유" 버튼

바텀시트 모달 컴포넌트 하나가 두 단계를 오간다.

1. **탭** → 모달 열림.
2. **입력 단계**: 비밀번호 입력 필드 + `공유하기` 버튼. 인솔자가 직접 입력한다.
   - 이미 공유된 여행(`trip.sharePassword` 존재)이면 이 단계를 건너뛰고 결과 단계로 바로 간다
     (저장된 비번으로 재게시/표시).
3. `공유하기` → 서버 게시(`POST /api/share/:shareId`) 성공 시 **결과 단계**로 전환:
   - 📎 참여 링크(`/join/:shareId`)와 🔑 비밀번호를 텍스트로 표시.
   - `복사` — 링크+비번을 한 번에 클립보드로. `navigator.clipboard` 실패 시 조용히 무시하되
     텍스트는 화면에 남아 있어 수동 복사 가능.
   - `카카오톡 등으로 공유` — `navigator.share({ text })`로 링크+비번을 휴대폰 공유시트에 전달.
     `navigator.share` 미지원이면 이 버튼을 렌더하지 않는다(복사로 대체).
   - **QR 코드** — 참여 링크를 인코딩해 표시. 학생이 카메라로 스캔하면 참여 페이지가 열리고,
     거기서 비밀번호를 입력한다(비번은 QR/링크에 포함하지 않음).
4. **에러**: 서버 실패 시 모달 안에 빨간 문구로 표시(네이티브 alert 금지).

### B. 삭제 흐름 — 여행 카드 "삭제" 버튼

- **탭** → 확인 모달: "'○○' 여행의 모든 데이터(사진·일정·미션 등)가 삭제되며 되돌릴 수
  없습니다." + `삭제`(위험색)·`취소`.
- `삭제` → 기존 `deleteTrip(tripId)` 호출. `취소` → 모달 닫기.

### C. 컴포넌트/데이터 흐름

- **`publishShare` 순수화**: `window.prompt`를 제거하고 시그니처를
  `publishShare(tripId: number, password: string)`로 바꾼다. 비번 결정(입력/기존값)은
  호출부(모달)가 담당한다. 서버 게시·`db.trips.update(shareId, sharePassword)`·URL 반환 로직은 유지.
- **모달 UI**: `src/pages/Trips.tsx` 안(또는 근처 파일)에 `ShareDialog`, `ConfirmDialog`를 둔다.
  `TripCard`는 콜백(`onShare`, `onDelete`)만 받고, 모달 상태는 `Trips` 상위에서 관리
  (어느 여행에 대해 열렸는지 `shareTrip`/`deleteTrip` 상태로 추적).
- **QR 생성**: 오프라인 안전(엄격 CSP·PWA)을 위해 **경량 QR 라이브러리를 번들**한다(CDN 금지).
  링크 문자열 → SVG 또는 data-URL 이미지. (후보: `qrcode`류 경량 패키지)
- **폴백**: `navigator.share`·`navigator.clipboard` 존재 여부를 확인해 조건부 렌더/처리.

### D. 테스트

- **단위**(`scripts/test-share.mjs` 확장 또는 신규): `publishShare` 순수화 후, 목 fetch로
  "비번 인자를 그대로 서버에 전송하고 shareId/URL을 반환한다"를 검증.
- **브라우저 스모크**(Playwright, `scripts/smoke-*.mjs`): 공유 모달 열기→비번 입력→결과 화면에
  링크·비번·QR 표시 확인, 삭제 확인 모달 동작 확인. 네이티브 대화상자에 의존하지 않으므로
  자동화로 전 흐름 검증 가능.

## 검증

- 데스크톱: 공유 모달로 게시→결과(링크/비번/복사/QR) 표시, 삭제 확인 모달 동작.
- 모바일(실기기/인앱 브라우저): 버튼 탭 시 모달이 뜨고 무반응 문제가 사라짐.
- 배포본(`triporganizer-app.vercel.app`)에서 실제 확인.
